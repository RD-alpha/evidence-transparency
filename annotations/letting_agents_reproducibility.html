Reproducibility of the full pipeline: letting agent fees, five end-to-end runs¶

The live pipeline (web_app/analyse.py, run_analysis) was run five times from scratch on one document, with every LLM step repeated: sentence extraction (Sonnet), core-theme finding (Sonnet), grouping around the core themes (Haiku) and scoring (Sonnet). Each run is on its own copy of documents/letting_agent_fees (letting_agent_fees_rep1 to _rep5) and writes to results/letting_agent_fees_rep{1..5}/.

This extends agreement_analysis.ipynb (extraction self-consistency on state pension, sections 5-8) and scoring_reproducibility.ipynb (scoring noise, fixed and varying extraction), which looked at the steps one at a time. Here all steps vary together, and the new core-theme step is included. The document was chosen as the highest-rated small document in the 2018 comparison (547 sentences; 2018 scored it 2/2/2/2; the earlier single run used in the 2018 comparison, from a separate experiment script, scored 2/2/1/0).

  1. Extraction: overlap in the sentences each run assigns to each aspect (Cohen's and Fleiss' kappa, per-sentence stability).
  2. Core themes: how much the named core themes and their sentences move between runs.
  3. Scores: how much the four aspect scores and the total move, set against the earlier fixed-extraction repeats.
  4. Cost and time.

Everything is read from persisted artefacts; no LLM calls are made here.

def fleiss_kappa(counts):
    """counts[i, j] = number of raters putting item i in category j."""
    n_items = counts.shape[0]; n = counts.sum(axis=1)[0]
    p_i = (np.square(counts).sum(axis=1) - n) / (n * (n - 1))
    p_j = counts.sum(axis=0) / (n_items * n)
    pe = np.square(p_j).sum()
    return np.nan if pe == 1 else (p_i.mean() - pe) / (1 - pe)

def variability(runs_df):
    pcts, kappas = [], []
    for a, b in combinations(runs_df.columns, 2):
        pcts.append((runs_df[a] == runs_df[b]).mean()); kappas.append(cohen_kappa_score(runs_df[a], runs_df[b]))

Was a single run representative?¶

Each run against the majority vote of all runs (an assignment made by at least half the runs), per aspect: Cohen's kappa.

The last two columns are the mean and the sample standard deviation of the five kappas for that aspect: a high mean with a small SD means any single run is a good stand-in for the majority; a large SD means some runs are far from it.

2. Core themes¶

For diagnosis, proposal and implementation, find_core names two to four core themes from the whole document; the grouping step then assigns each sentence in the aspect to a theme, and a section's score is the mean of the core themes' levels. Testing is scored as one block and has no core themes. Two things can move between runs: which themes are named, and which sentences end up in them.

def core_names(d, a):
    p = d / "core_themes.json"
    return [t["name"] for t in json.loads(p.read_text())[a]["core_themes"]] if p.exists() else []

def core_ids(d, a):
    w = d / a / "weights.json"; c = d / a / "classification.json"
    if not (w.exists() and c.exists()): return set()
    core = {t["theme"] for t in json.loads(w.read_text())["themes"] if t["weight"] == "core"}
    return {i for t in json.loads(c.read_text())["themes"] if t["name"] in core for i in t["ids"]}

Where do scores come from: the core means¶

The score is the rounded mean of the core themes' levels, so a score flips when the mean crosses a boundary (x.5 rounds down). core_mean is that mean before rounding. A run whose mean sits near a half is on the edge.

Extraction stability of the sentences that feed the scores¶

A score is built only from the core sentences: those that the grouping step places in a core theme. So the question that matters for scoring is not how stable extraction is overall (above) but how stable it is for the sentences that end up core. A core sentence can be missing from another run in two ways: it was not extracted for that aspect at all (step 1), or it was extracted but not placed in a core theme (steps 2-3, which depend on the themes named).

First, for every sentence that is core in at least one run, how many of the five runs extracted it into the aspect, set against sentences that were extracted but never core. Fisher's exact test compares the share extracted by all five runs in the two groups.

3b. Nested design: repeating the downstream steps on each extraction¶

The five full runs vary extraction and everything after it together. To separate the two, the later steps (core-theme finding, grouping, scoring) were repeated twice more on each of the five extractions, with the extraction held fixed (scripts/stability_runs.py find_core, find_core_grouping, find_core_score; results in results/letting_agent_fees_rep{n}/stability/find_core_run{1,2}). Together with the original live run on that extraction, this gives 5 extractions x 3 downstream repeats = 15 scores per aspect. A one-way random-effects ANOVA then splits the variance of each score into a component between extractions and a component within an extraction (downstream noise); the extraction share is the ICC(1).

def components(X):
    n, k = X.shape
    msb = k * X.mean(1).var(ddof=1); msw = X.var(axis=1, ddof=1).mean()
    sb = max((msb - msw) / k, 0.0)
    return sb, msw, (sb / (sb + msw) if sb + msw > 0 else np.nan)

Summary (2026-10-09)¶

Five complete runs of the live pipeline on letting agent fees (547 sentences), every LLM step repeated. A sixth attempt (the first try of run 5) was truncated at the extraction step and is not included.

Extraction

  • Per aspect (Yes/No, five runs). Fleiss' kappa 0.61 for diagnosis, 0.73 for proposal and 0.75 for implementation; mean pairwise Cohen's kappa 0.64 (range 0.42-0.93), 0.73 (0.61-0.88) and 0.75 (0.60-0.92). 73%, 88% and 87% of sentences get the same call in all five runs. Testing is undefined: no run extracts a single testing sentence. For comparison, state pension (same extraction call, five runs) gave Fleiss' kappa 0.90, 0.79, 0.73 and 0.81. So proposal and implementation are about as reproducible as on state pension; diagnosis is clearly less so.
  • Diagnosis has two modes. Sentences flagged range from 91 to 234 across runs (proposal 58-90, implementation 68-117). Runs 1 and 5 (188 and 234) read "diagnosis" broadly, taking in general market background, and agree with each other (all-category kappa 0.78) but less with runs 2-4 (0.55-0.67); runs 3 and 4 agree most closely (0.88). "Diagnosis vs none" accounts for 55% of all run-pair label disagreements.
  • All categories together. Cohen's kappa averages 0.69 (0.55-0.88) and Fleiss' kappa is 0.68; 65% of sentences (354 of 547) get the same label in every run.

Core themes

  • Every aspect gets 3-4 named core themes in every run (four in 14 of 15 aspect-runs). The themes recur in substance (fee level and opacity; weak tenant market power and misaligned incentives; failure of existing regulation; for proposals, a fee ban to rebalance the market, the Scottish precedent, scope of the ban, pass-through) but the wording and the fourth theme chosen vary.
  • Core sentences overlap moderately: mean pairwise Jaccard 0.74 for diagnosis, 0.67 for proposal and 0.58 for implementation (minima 0.62, 0.57 and 0.33), Fleiss' kappa 0.83, 0.78 and 0.67. Of the sentences that are core in at least one run, only 44 of 83 (diagnosis), 24 of 58 (proposal) and 37 of 117 (implementation) are core in all five.

Extraction stability of the core sentences. What matters for a score is the extraction of the sentences that end up in core themes, and these are much more stable than extraction overall. Of the sentences that are core in at least one run, 67% (diagnosis), 76% (proposal) and 49% (implementation) were extracted by all five runs, against 19%, 5% and 8% of sentences that were extracted but never core (Fisher's exact p = 1.5e-13, 8.3e-16 and 0.012). A sentence that is core in one run is also core in another run 85%, 80% and 71% of the time. The core is lost mostly through extraction for diagnosis (69% of losses: the other run did not extract the sentence) and implementation (53%), but mostly through the theme and grouping steps for proposal (66%: extracted, but outside a core theme). The instability is concentrated in a few runs: 42 of the 46 implementation core sentences that two or fewer runs extracted sit in run 2, whose core has 98 sentences against 45-64 elsewhere (48% robust against 84-98%), and diagnosis runs 2 and 5 (the broad readings) carry 13 and 17 fragile core sentences against 0-4 elsewhere. In these five runs the scores did not follow that: run 2's implementation score was the modal 1, so the extra fragile sentences widened the core without changing its level.

Scores

  • Diagnosis 2, 2, 1, 2, 2; proposal 1, 1, 1, 1, 2; implementation 1, 1, 1, 1, 0; testing 0 in all five. Each aspect has a modal score in four of five runs. Only testing is identical in all five. Over all run pairs 70% of aspect scores are identical and 100% are within one level; the total (out of 12) is 3 or 4 in four runs and 4 in the fifth, mean 3.8, SD 0.45, identical in 60% of pairs and within one point in all; ICC(1,1) across aspects is 0.78.
  • Where the score moves it is mostly at a rounding boundary: four of the 15 core aspect scores have a core mean of exactly x.5 (proposal 1.5 in runs 1 and 3, diagnosis 1.5 in run 3, implementation 0.5 in run 5), and exact halves round down. Rounded up, the proposal scores would be 2, 1, 2, 1, 2 and the implementation scores all 1, giving totals of 5, 4, 5, 4, 5 (computed from the core means above).
  • Nested design (the later steps repeated three times on each of the five extractions, 15 scores per aspect). The extraction share of the variance in the total score is about a quarter (ICC 0.25; bootstrap interval 0.00-0.36, very wide with five extractions): the standard deviation of a total is 0.39 between extractions and 0.68 within an extraction, so re-running core-theme finding, grouping and scoring on identical sentences moves the total more than changing the extraction does. By aspect it differs. Diagnosis is almost all downstream noise (extraction share 5%; SD 0.11 between, 0.45 within), even though diagnosis extraction is the least reproducible step. Proposal is about even (48%) and implementation is mostly extraction (71%; extraction 5 scores 0 in all three repeats, extraction 3 scores 0 once). Identical-score rates for pairs on the same extraction against pairs on different extractions: diagnosis 60% against 58%, proposal 73% against 49%, implementation 87% against 53%, total 27% against 40% (totals within one point: 93% against 82%). Core-sentence overlap is higher on the same extraction (Jaccard 0.80, 0.63 and 0.81 for diagnosis, proposal and implementation) than across extractions (0.66, 0.54 and 0.68).
  • Against the older fixed-extraction repeats. Three earlier repeats on one older extraction gave totals 5, 4, 5 and proposal 2 every time; the fresh runs give 3-5 with proposal 1 or 2. That may mean the older extraction was an unusual draw, but it cannot be shown from five.

What it means for the comparison with 2018. 2018 scored this document 8 (2/2/2/2); the five runs score 3-4. The gap of about four points is roughly nine times the run-to-run SD of the total, so noise in the pipeline does not explain the gap with 2018; reproducibility is adequate for ranking documents but the level is consistently lower. The earlier 20-document comparison used the older single run (total 5) for this document, which is the high end of what this pipeline produces.

Cost and time. The four first-attempt runs cost $0.70-0.84 each (mean $0.77) and took 7.7-9.9 minutes. The first attempt at run 5 hit the 75,000-output-token cap at the extraction step, was truncated and produced nothing ($0.81, 10.4 minutes); the rerun cost $0.77. The ten downstream-only repeats cost $2.96 (about $0.30 each, 70 calls, roughly 35 minutes). Total spend on this study $7.61 ($4.65 for the five full runs including the failed attempt, plus $2.96); the cost table in section 4 totals every call charged to each run folder, so it includes both. One truncation in six extraction calls on this document is itself a reliability finding: the extraction output cap can be reached.

Caveats: one document and five runs; core themes are compared through their sentences, not matched by name automatically; kappa for testing cannot be computed because nothing is extracted; the 2018 scores are not ground truth.
